# Designing Google Cloud Networks and Load Balancers

## Google Cloud Network

- **Worldwide Network**: Connects regions globally.
- **High-Bandwidth Infrastructure**: Design networks to meet requirements like location, number of users, scalability, fault tolerance, and latency.

## Google Cloud's Reach

- **Regions**: Specific geographical locations to run resources.
- **Points of Presence (PoPs)**: Interconnection points to the rest of the Internet.
- **Global Private Network**: Composed of fiber optic cables and submarine cable investments.

## VPC Networks

- **Global VPC Networks**: Create auto mode networks with one subnet per region or custom mode networks specifying regions for subnets.
- **Internal Communication**: Resources across regions can communicate using internal IP addresses without added interconnect.
- **Subnet Selection**: Depends on requirements; global companies may create subnets in multiple regions.

## Custom Subnets

- **Creation**: Specify region and internal IP address range.
- **Non-Overlapping IP Ranges**: Subnet IP ranges cannot overlap within the same VPC network.
- **Primary and Secondary Ranges**: Define alias IP addresses and expand primary IP address space without downtime.

## Multiple Network Interfaces

- **VM Network Interfaces**: A single VM can have multiple network interfaces connecting to different VPC networks.
- **Instance Creation**: All network interfaces must be created when the instance is created, each attached to a different network.

## Shared VPC

- **Organization-Wide Connectivity**: Connect resources from multiple projects to a common VPC network.
- **Secure Communication**: Resources communicate securely using internal IPs.
- **Centralized Networking**: Security and network policy managed in a single VPC network.
- **Delegated Control**: Network administrators maintain control of resources, while service project administrators or developers create instances.

# Load Balancers

## Global Load Balancers

- **Access to Services**: Provide access to services deployed in multiple regions.
- **Example**: Backend with instance groups in different regions, load distributed using Cloud Load Balancing.
- **Supported by**: HTTP load balancers, TCP and SSL proxies.
- **Global Anycast IP**: Simplifies DNS lookup, routes requests to the closest region by default.

## Regional Load Balancers

- **Single Region**: Use for services deployed in a single region.
- **Support**: HTTP and any TCP or UDP port.

## Securing Traffic

- **Public IP Addresses**: Traffic likely traverses the Internet.
- **SSL**: Secure traffic with SSL for HTTP and TCP load balancers.
- **Certificates**: Use self-managed or Google-managed SSL certificates.

## Cloud CDN

- **Lower Latency and Decrease Egress Costs**: Enable Cloud CDN for HTTP(S) load balancing.
- **Edge-Caching Locations**: Caches content closest to the user.
- **Sources**: Data cached from Compute Engine instances, GKE pods, or Cloud Storage buckets.

## Load Balancer Types and Capabilities

- **Internal or External IP Addresses**: External IPs are internet-facing.
- **Regional or Multi-Regional**: Supports different traffic types (HTTP, TCP, UDP).

### Traffic Types

1. **HTTP(S) Load Balancing**
   - **Layer 7**: Supports HTTP, HTTPS, including HTTP/2.
   - **Load Balancing**: Internet-facing and internal, regional or global.

2. **TCP Load Balancing**
   - **Layer 4**: Balancing or proxy for TCP/SSL protocol.
   - **Configuration**: TCP load balancer or TCP/SSL proxy.
   - **Load Balancing**: Internet-facing and internal, regional or global.

3. **UDP Load Balancing**
   - **Protocol**: For applications relying on UDP.
   - **Load Balancing**: Internet-facing and internal, regional only.

# Google Cloud Network Connectivity Products

## VPC Peering

- **Private Connectivity**: Allows private RFC 1918 connectivity across two VPC networks, regardless of project or organization.
- **Firewall Rules**: Each VPC network has firewall rules defining allowed or denied traffic.
- **Subnet Ranges**: Must not overlap for a connection to be established.
- **Configuration**: Network administrators must configure a VPC peering request for connection.

## Cloud VPN

- **Secure Connection**: Connects on-premises network to Google Cloud VPC network through an IPsec VPN tunnel.
- **Encryption**: Traffic is encrypted by one VPN gateway and decrypted by another.
- **SLA**: 99.9% monthly uptime for classic VPN, 99.99% for high availability VPN.
- **Classic VPN**: Single interface and external IP address.
- **HA VPN**: Two interfaces with two external IP addresses, supports higher availability.
- **Routing**: Supports site-to-site VPN, static routes (classic VPN), and dynamic routes using Cloud Router.
- **MTU Consideration**: Maximum transmission unit for on-premises VPN gateway cannot be greater than 1,460 bytes.

## HA VPN

- **High Availability**: Provides 99.99% service availability.
- **Configuration**: Requires two or four tunnels from HA VPN gateway to peer VPN gateway or another HA VPN gateway.
- **Dynamic Routing**: VPN tunnels must use dynamic routing (BGP).
- **Topologies**: Supports HA VPN gateway to peer VPN devices, AWS virtual private gateway, or two HA VPN gateways connected to each other.

## Cloud Router

- **Dynamic Routes**: Manages routes for Cloud VPN tunnel using Border Gateway Protocol (BGP).
- **Route Updates**: Allows routes to be updated and exchanged without changing tunnel configuration.

## Cloud Interconnect

- **Dedicated Interconnect**: Direct connection to a co-location facility, supports 10 Gbps or 100 Gbps circuits.
- **Partner Interconnect**: Connection through a service provider, useful for lower bandwidth requirements starting from 50 Mbps.
- **Internal IP Address Space**: Allows access to VPC resources using internal IP addresses.
- **Private Google Access**: Configure for on-premises hosts to access Google services using private IP addresses.
- **Provisioning**: Requires provisioning a cross connect between Google network and your router in a common co-location facility.
- **BGP Session**: Configure BGP session over the interconnect between Cloud Router and on-premises router.

## Example Configurations

1. **Classic VPN Connection**: Connects VPC and on-premises network with subnets in different regions.
2. **HA VPN Gateway to Peer Devices**: Provides redundancy and failover with two peer devices.
3. **HA VPN Gateway to AWS Virtual Private Gateway**: Uses transit gateway or virtual private gateway, supports ECMP route.
4. **HA VPN Gateway to Another HA VPN Gateway**: Connects two Google Cloud VPC networks together, provides 99.99% availability.
