# Maintenance and Monitoring

- **Maintenance**:
  - Concerned with how updates are made to running applications.
  - Different strategies available and how different deployment platforms support them.

- **Monitoring**:
  - Vital for cloud-native applications from two perspectives:
    - **Cost Perspective**:
      - Ensure resources are provisioned against demand.
      - Avoid paying for unnecessary resources.
    - **Health Perspective**:
      - Implement monitoring and observability to determine and alert on the health of services and applications.
      - Use Cloud Monitoring and Dashboards.
      - Define Uptime Checks and use Cloud Monitoring Alerts to identify service outages.

# Version Management

- **Microservice Architecture**:
  - Key benefit: Ability to independently deploy microservices.
  - Service API must be protected.
  - Versioning is required to ensure backward compatibility.
  - Indicate version in the URI and change the version for backward-incompatible changes.

- **Deploying New Versions**:
  - Test new versions effectively before going live.
  - Deploy new versions with zero downtime.

- **Deployment Strategies**:
  - **Rolling Updates**:
    - Deploy new versions with no downtime.
    - Update one instance at a time behind a load balancer.
    - Suitable if the API is not changed or is backward compatible.
    - Built-in feature for instance groups, default in Kubernetes, and automated in App Engine.

  - **Blue-Green Deployment**:
    - Avoid running multiple versions of a service simultaneously.
    - Use twofold deployment environments (blue for current, green for new).
    - Deploy new version to green environment, test, then shift workload from blue to green.
    - Mitigates risk by allowing switchback to previous deployment if needed.
    - Use DNS for Compute Engine, labels for Kubernetes, and traffic splitting for App Engine.

  - **Canary Releases**:
    - Deploy new version alongside current deployment.
    - Send a small percentage of traffic to the new deployment and monitor.
    - Gradually route more traffic to the new deployment until 100% is routed.
    - Create a new instance group for Compute Engine, new pod with same labels for Kubernetes, and use traffic splitting for App Engine.

# Cost Planning

- **Capacity Planning**:
  - Treat capacity planning as a continuous, iterative cycle.
  - Start with a forecast to estimate capacity needed.
  - Monitor and review the forecast.
  - Allocate resources to meet forecasted capacity.
  - Estimate costs and balance them against risks and rewards.
  - Deploy design and monitor accuracy of forecasts.
  - Repeat the process for continuous improvement.

- **Cost Optimization**:
  - Familiarize with VM instance pricing.
  - Start with small machines that can scale out through auto scaling.
  - Use committed use discounts for significant savings.
  - Consider Spot instances for fault-tolerant applications to reduce costs by up to 91%.
  - Use Compute Engine's sizing recommendations for VM instances.

- **Disk Space Allocation**:
  - Avoid over-allocating disk space.
  - Determine performance characteristics of applications (I/O patterns).
  - Select the correct type of disk based on application needs.
  - SSD persistent disks are more expensive than standard persistent disks.

- **Network Costs**:
  - Keep machines close to the data they need to access.
  - Be aware of egress charges (within the same zone, between zones, intercontinental, and internet egress).
  - Optimize network costs by keeping machines close to data.

- **GKE Usage Metering**:
  - Prevent over-provisioning Kubernetes clusters.
  - Collect consumption metrics and resource requests.
  - Export records to BigQuery for analysis.
  - Compare requested with consumed resources to spot waste.

- **Storage and Database Services**:
  - Compare costs and characteristics of different storage options.
  - Use Cloud CDN for static content and Memorystore as a cache to save resources.
  - Consider message/queuing with Pub/Sub to reduce storage needs.

- **Pricing Calculator**:
  - Use the pricing calculator for estimating costs based on forecasting and capacity planning.
  - Compare costs between compute and storage services.

- **Monitoring Costs**:
  - Use Cloud Billing Reports to monitor cost changes and filter by projects, products, and regions.
  - Export billing data to BigQuery for advanced cost analysis.
  - Visualize spend over time with Looker Studio.

- **Setting Budgets**:
  - Set a budget to track spending.
  - Specify project, set budget amount, and configure alerts.
  - Use Pub/Sub notifications for programmatic spend updates.
  - Automate cost management with Cloud Functions.
