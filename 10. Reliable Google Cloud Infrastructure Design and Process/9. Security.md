# Security

- **Google's Security Approach**:
  - Google has been operating securely in the cloud for 20 years.
  - Security empowers innovation.
  - Security should be prioritized by cloud architects; everything else follows.

- **Designing Secure Systems**:
  - Apply the principle of least privilege.
  - Practice separation of concerns.
  - Perform regular audits.
  - Use Google's Security Command Center to identify vulnerabilities.

- **Governance**:
  - Organization policies and folders simplify governance.

- **Preventing Unauthorized Access**:
  - Authentication and authorization are key.
  - Implement IAM roles, Identity-Aware Proxy, and Identity Platform.
  - Manage access and authorization of resources by machines and processes using service accounts.

- **Network Access Control**:
  - Secure network access using private IPs, firewalls, and Google Cloud private access.

- **Mitigating DDoS Attacks**:
  - Leverage Cloud DNS and Google Cloud Armor.

# Security Concepts and Best Practices

- **Google Cloud Security**:
  - Google handles many lower layers of the security stack.
  - Google delivers a higher level of security at these layers due to its scale.
  - Security is a shared responsibility between you and Google.
  - Clear separation of duties and transparency are essential.
  - Google provides controls, features, and tools to monitor services.
  - Security is implemented in layers, from custom-built hardware to verified boot loading systems.

- **Your Role in Security**:
  - Establish firewall rules and configure IAM correctly.
  - Use Google Cloud's tools for monitoring and auditing networks or install your own tools.

- **Best Practices for Implementing Security**:
  - **Principle of Least Privilege**:
    - Grant users only the minimal set of permissions required.
    - Apply this principle to machine instances, processes, and users.
    - Use Cloud IAM to identify users and machines, and assign roles to restrict actions.

  - **Separation of Duties**:
    - Prevent conflict of interest and detect control failures.
    - Ensure no one person can change or delete data without detection.
    - Use multiple projects to separate duties and assign suitable rights.
    - Organize multiple projects using folders.

  - **Auditing**:
    - Audit Google Cloud logs to discover attacks and potential security breaches.
    - Logs include admin, data access, VPC flow, firewall, and system logs.

- **Compliance**:
  - Maintain compliance with regulatory requirements or guidelines.
  - Google Cloud meets many third-party and government compliance standards.
  - Your application running on Google Cloud must also be certified secure.

- **Security Command Center**:
  - Provides access to organizational and project security configuration.
  - Dashboard reports security health analysis, threat detections, anomaly detection, and summary reports.
  - Provides actionable recommendations once a threat is detected.

# Securing People

- **Granting Access**:
  - Add people as members and assign them one or more roles.
  - Roles are lists of permissions.
  - Use the Cloud Console to see permissions granted to roles.
  - Assign predefined roles or customize your own roles.

- **Managing Members and Permissions**:
  - Create groups to simplify management.
  - Adding members to a group automatically grants them the group's permissions.
  - Removing members from a group also removes the group's permissions.

- **Organizational Policies and Folders**:
  - Use organizational policies and folders to simplify securing environments and managing resources.
  - Organizational policies apply to all resources underneath an organization.
  - Cloud IAM policies are inherited top to bottom (organization -> folders -> projects).

- **Best Practices for Roles**:
  - Grant roles to groups, not individuals, for easier management.
  - Define groups carefully and make them more granular than job roles.
  - Use multiple groups for better control.
  - Prefer predefined roles over custom roles.
  - Follow the principle of least privilege when granting roles.
  - Limit owner and editor roles as they are not required by the majority of users.

- **Cloud Identity-Aware Proxy (Cloud IAP)**:
  - Provides managed access to applications running in App Engine, Compute Engine, and GKE.
  - Allows secure access to web-based applications without requiring a VPN.
  - Administrators control access, and users must log on to gain access.

- **Identity Platform**:
  - Customer Identity and Access Management (CIAM) platform for adding Identity and Access Management to applications.
  - Provides sign-up and sign-in for end-user applications.
  - Supports a broad range of protocols, including SAML, OpenID, email and password, phone, social, and Apple.

# Securing Machine Access

- **Service Accounts**:
  - Special kind of account used by applications, virtual machine instances, or GKE node pools.
  - Used to make authorized API calls.
  - Defines permissions controlling the resources the service can access.
  - Acts as both an identity and a resource.

- **Using Service Accounts**:
  - Authenticate applications or services (e.g., a Compute Engine VM running as a service account).
  - Grant relevant Cloud IAM roles to the service account for resource access.
  - Control who can create VMs with the service account to prevent unauthorized use.
  - Assign the ServiceAccountUser role to trusted users.

- **RSA Key-Pairs**:
  - Each service account is associated with public/private RSA key-pairs for authentication.
  - Keys can be Google-managed or user-managed.
  - Google-managed keys are stored and rotated by Google (maximum usage period: two weeks).
  - User-managed keys are owned by the developer and can be used from outside Google Cloud.
  - Manage user-managed keys via Cloud IAM API, gcloud command-line tool, or Cloud Console.
  - Create up to 10 key-pairs per service account to support key rotation.

- **Managing User-Managed Keys**:
  - User-managed keys are powerful credentials and can pose a security risk if not managed correctly.
  - Limit their use with the `constraints/iam.disableServiceAccountKeyCreation` Organization Policy Constraint.
  - Enable user-managed keys in well-controlled locations.
  - Use Cloud Key Management Service (Cloud KMS) to securely manage keys.

- **Key Generation and Management**:
  - Generate keys using the Cloud Console.
  - Store the private key securely.
  - Configure the gcloud command-line utility to use service account credentials for controlled access to resources.
  - Use `gcloud auth activate-service-account` to authenticate with service account credentials instead of user credentials.
  - The key file contains the private key in JSON format.

# Network Security Concepts

- **Removing External IPs**:
  - Prevent access to machines from outside their network whenever possible.
  - Options for securely communicating with VMs without public IP addresses:
    - Bastion host for external access to private machines.
    - Identity-Aware Proxy (IAP) to enable SSH access.
    - Cloud NAT to provide egress to the Internet for internal machines.

- **Accessing Google Services**:
  - VM instances with internal IP addresses can use private Google access to access Google services with external IP addresses.
  - Enable private Google access when creating the subnet via G Cloud command or Cloud Console.

- **Firewall Rules**:
  - Configure firewall rules to control access regardless of public IP addresses.
  - By default, ingress on all ports is denied, and all egress is allowed.
  - Define rules to allow or deny access to specific instances for specific IP ranges, protocols, and ports.

- **Managing APIs**:
  - Use Cloud Endpoints to develop, deploy, and manage APIs on any Google Cloud backend.
  - Protect and monitor public APIs, control access, and validate calls with JSON Web Tokens.
  - Integrate Cloud Endpoints with Identity Platform for authentication.
  - Use HTTPS for all Google Cloud Service Endpoints and configure service endpoints for TLS.

- **Load Balancers and DDoS Protection**:
  - Only create secure front ends for load balancers (use HTTPS).
  - Google provides Infrastructure DDoS support through global load balancers at level 3 and level 4 traffic.
  - Enable CDN to protect backend resources from DDoS attacks.

- **Google Cloud Armor**:
  - Create network security policies for additional DDoS protection.
  - Create allow lists for known/required addresses and deny lists to block known attackers.
  - Supports layer 7 application rules (e.g., cross-site scripting, SQL injection attacks).
  - Provides a rules language for filtering request traffic.

- **Example Expressions**:
  - `origin.ip in [9.9.9.0/24]`: Returns true if the origin IP is within the specified range.
  - `request.headers['cookie'].contains('80=BLAH')`: Returns true if the specified cookie exists in the request header.
  - `origin.region_code == 'AU'`: Returns true if the origin region code is AU.
  - Combine expressions with logical AND and OR.
  - Assign expressions to allow or deny rules for incoming traffic.

## Encryption

- **Default Encryption**:
  - Google Cloud encrypts customer data stored at rest by default.
  - Uses AES 256 symmetric key for data encryption key (DEK).
  - DEK is encrypted by a key encryption key (KEK) and stored locally for fast decryption.
  - KEKs are stored in Cloud KMS and rotated periodically and automatically.

- **Customer Managed Encryption Keys (CMEK)**:
  - Use Cloud Key Management Service (Cloud KMS) to generate CMEKs.
  - CMEKs are stored in Cloud KMS for direct use by cloud services.
  - Manually create keys and specify rotation frequency (default: 90 days).
  - Use CMEKs when creating storage resources like disks or buckets.

- **Customer Supplied Encryption Keys (CSEK)**:
  - Generate and manage encryption keys on premises.
  - Keys are provided as part of API service calls and only kept in memory for decryption.
  - Currently supported with Cloud Storage and Compute Engine.

- **Data Loss Prevention (DLP) API**:
  - Protect sensitive data by finding and redacting it.
  - Provides fast, scalable classification and redaction for sensitive data elements (e.g., credit card numbers, social security numbers, phone numbers, Google Cloud credentials).
  - Uses more than 90 predefined detectors to identify patterns, formats, and checksums, and understands contextual clues.
  - Redaction techniques include masking, secure hashing, tokenization, bucketing, and format-preserving encryption.
