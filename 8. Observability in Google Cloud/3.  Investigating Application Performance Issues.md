# Investigating Application Performance Issues

When deploying applications to Google Cloud, the Application Performance Management products (Cloud Trace and Cloud Profiler) provide insight into how your code and services are functioning. The tools also help troubleshoot when needed.

## Learning Objectives

- Explain the features and benefits of Error Reporting, Cloud Trace, and Cloud Profiler.
- List and explain the functionalities of the Error Reporting, Cloud Trace, and Cloud Profiler components.

## Application Performance Management (APM)

APM combines the monitoring and troubleshooting capabilities of Cloud Logging and Cloud Monitoring with Error Reporting, Cloud Trace, and Cloud Profiler. APM helps you reduce latency and cost so that you can run more efficient applications.

## Error Reporting

- **Functionality**: Looks through all the logs that your application and infrastructure have reported. Counts, analyzes, and aggregates the exceptions to report them on your preferred notification channel such as email, mobile app, Slack, or through web hooks.
- **Limitations**: Can only analyze log entries stored in Cloud Logging buckets in the global region. The source and destination Google Cloud projects must be the same, and customer-managed encryption keys (CMEK) must be disabled.
- **Features**:
  - Helps understand errors by providing a clear dashboard of top or new errors.
  - Brings processed data directly to help understand and fix root causes faster.
  - Intelligently aggregates problems into meaningful groups tailored to your programming language and framework.
  - Provides instant error notification and alerts you when a new application error cannot be grouped with existing ones.
  - Available on desktop and in the Google Cloud app for iOS and Android.
  - Supports many popular languages, including Go, Java, Node.js, PHP, Python, Ruby, and .NET.
  - Can aggregate and display errors for various environments like App Engine, Cloud Run, Compute Engine, Amazon EC2, and Google Kubernetes Engine (GKE).

## Setting Up Error Reporting

- **Node.js Example**:
  - Needs the Error Reporting Writer Identity and Access Management role.
  - Enable the Error Reporting API and install the client library using npm.
  - Import the Error Reporting library and instantiate a client to start reporting errors.
  - Customize the behavior of the Error Reporting library by passing objects to options.
  - Use the error message builder to customize all fields and call the report method to manually report an error.
  - Integrate the Error Reporting library with web frameworks like Express.js.

- **Google Cloud Environments**:
  - **App Engine**: Automatically enabled for both flexible and standard environments.
  - **Cloud Run**: Automatically enabled.
  - **Google Kubernetes Engine**: Add cloud-platform access scope during cluster creation.
  - **Compute Engine**: Ensure the service account used has the Error Reporting Writer role.
  - **Outside Google Cloud**: Provide the Google Cloud project ID and service account credentials to the Error Reporting library for Node.js.

## Viewing Errors

- Open the Error Reporting page in the Google Cloud console.
- By default, shows a list of recently occurring open and acknowledged errors in order of frequency.
- Errors are grouped and de-duplicated by analyzing their stack traces.
- Auto reload feature reloads the error list every 10 seconds.
- Recognizes common frameworks used for your language and groups errors accordingly.
- Sort errors based on occurrences (first and last seen).
- Link an issue tracker to an error group by clicking the + icon below Insert link.
- Expand into the Error Details page to examine information about the error group, including the history of a specific error, specific error instances, and diagnostic information.
- View the log entry associated with a sample error by clicking View logs from any entry in the Recent samples panel, which takes you to Logs Explorer in the Cloud Logging console.

# Cloud Trace

Cloud Trace is a distributed tracing system that collects latency data from your applications and displays it in the Google Cloud console. It allows you to track how requests propagate through your application and receive detailed near-real-time performance insights.

## Features and Benefits

- **Latency Data Collection**: Automatically analyzes all application traces to generate in-depth latency reports and surface performance degradations.
- **Issue Detection**: Continuously gathers and analyzes trace data to identify recent changes in application performance. Latency distributions can be compared over time or versions, and significant shifts trigger automatic alerts.
- **Performance Bottleneck Identification**: Inspects detailed latency information for single requests or aggregate latency for the entire application. Tools and filters help quickly find and identify root causes of bottlenecks.

## Platform Support

- **Broad Platform Support**: Language-specific SDKs for Java, Node.js, Ruby, and Go. Can analyze projects running on VMs, including those not managed by Google Cloud.
- **Trace API**: Used to submit and retrieve trace data from any source.

## Trace Structure

- **Trace**: Describes the time it takes an application to complete a single operation. A trace is a collection of spans.
- **Span**: Describes the time it takes to perform a complete suboperation. For example, a trace might describe the time to process a user request, while a span might describe the time for a specific RPC call.

## Instrumentation

- **OpenCensus**: Simplifies creating and sending trace data, implements batching for improved performance.
- **Trace SDK Library**: Used if OpenCensus is not available. The Cloud Trace API collects and sends trace data to your Google Cloud project.

## Sending Trace Data

- **Automatic Tracing**: Supported configurations include:
  - App Engine standard environment with Java 8, Python 2, and PHP 5 applications.
  - HTTP requests and latency data from Cloud Run functions and Cloud Run.
- **Instrumenting the Application**: Use Google client libraries or OpenTelemetry (recommended).

## IAM Permissions

- **External Systems, Compute Engine, and GKE**: Ensure service accounts have at least the Cloud Trace Agent role.
- **Default Access**: App Engine, Cloud Run, Cloud Run functions, Google Kubernetes Engine, and Compute Engine have default access through the default Compute Engine service account.

## Analysis Reports

- **Overview**: Shows an overall view of latency for all requests or a subset of requests.
- **Custom Reports**: Can be created for specific request URIs and other search qualifiers. Reports can display results as density distributions or cumulative distributions.

   - Click **Activate Cloud Shell** in the Google Cloud console toolbar.

2. **Download Source Code**:

## View the Trace Data

1. **Open Cloud Trace**:
   - In the Google Cloud console, select **Cloud Trace**.
   - The **Overview** window displays latency data and summary information, including an analysis report.

2. **Recent Traces Pane**:
   - Displays the most recent traces and their latency.
   - Click a trace link to view details.

3. **Trace Explorer**:
   - Click **Trace explorer** in the navigation pane.
   - Displays a graph and a table. Each dot on the graph represents a trace.
   - Select a dot or a row to view trace details.
   - The **Trace details** pane shows information about the trace and spans.
   - Click the latency bar to view additional details about each span.

# Cloud Profiler

## Overview

Understanding the performance of production systems is notoriously difficult. Continuous profiling of production systems is an effective way to discover where resources like CPU cycles and memory are consumed when the service operates in its working environment.

## Features and Benefits

- **Low-Impact Production Profiling**: Provides a comprehensive application performance view without slowing it down.
- **Practical Application Profile Creation**: Continuously analyzes the performance of CPU or memory-intensive functions, presenting the call hierarchy and resource consumption in an interactive flame graph.
- **Broad Language and Product Support**: Supports applications running on Google Cloud and other platforms, including Java, Go, Node.js, and Python.

## Profiling Types

- **CPU Metrics**:
  - **CPU Time**: Time the CPU spends executing a block of code.
  - **Wall Time**: Total time to run a block of code, including wait times.
- **Heap Metrics**:
  - **Heap**: Memory allocated in the heap when the profile is collected.
  - **Allocated Heap**: Total memory allocated in the heap, including freed memory.
- **Thread Metrics**:
  - **Contention**: Information about threads waiting for other threads.
  - **Threads**: Thread counts.

## Setup and Instrumentation

- **Supported Environments**: Most Google and non-Google compute technologies (Windows guest OS not supported).
- **Python Application Example**:
  - Ensure the Profiler API is enabled.
  - Import the `googlecloudprofiler` package.
  - Install the C/C++ compiler, development tools, pip, and Profiler package.
  - Start the profiler early in your code, setting the logging level to verbose (3) for debug level.

## Using the Profiler Interface

- **Profile Selection**: Choose profiles to analyze by options such as Timespan, Service, Profile type, Zone, and Version.
- **Weight**: Limits the flame graph to particular peak consumptions (e.g., Top 5%).
- **Compare To**: Allows comparison of two profiles.
- **Flame Graphs**: Displays profiling data efficiently, representing a large amount of information in a compact format.

## Example Analysis

- **Flame Graph Interpretation**:
  - A basic application with a main method calling `foo1` and `foo2`, which in turn call `bar`.
  - CPU time analysis shows how time is spent in different methods.
  - Tooltip displays additional information such as function name, source file location, and metric consumption.
  - Clicking a frame redraws the graph, making the call stack of the selected method more visible.

## Conclusion

Cloud Profiler provides valuable insights into the performance characteristics of your application, helping you identify and optimize resource-intensive parts of your code.
