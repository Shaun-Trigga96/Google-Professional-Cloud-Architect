# Deploy and Troubleshoot a Website: Challenge Lab

## Overview

In this challenge lab, you will deploy a new website using a simple Apache web server on a Linux VM instance in Google Cloud. Follow the tasks below to complete the challenge.

## Setup and Requirements

- Use an Incognito or private browser window to run this lab.
- Do not use your personal Google Cloud account to avoid extra charges.

## Challenge Scenario

Your company is ready to launch a new product and you need to deploy a new website. The site is complete, but the person who built it left the company before deploying it. Your task is to deploy the site using a simple Apache web server.

## Tasks

### Task 1: Create a Linux VM Instance

1. Open Cloud Shell.
2. Create a Linux virtual machine named `dev-fin-oq6` in the `us-west1-a` zone:

    ```sh
    gcloud compute instances create dev-fin-oq6 \
        --zone=us-west1-a \
        --machine-type=e2-medium \
        --image-family=debian-10 \
        --image-project=debian-cloud \
        --tags=http-server
    ```

### Task 2: Enable Public Access to VM Instance

1. Create a firewall rule to allow HTTP traffic:

    ```sh
    gcloud compute firewall-rules create allow-http \
        --target-tags=http-server \
        --allow=tcp:80
    ```

### Task 3: Running a Basic Apache Web Server

1. SSH into the VM instance:

    ```sh
    gcloud compute ssh dev-fin-oq6 --zone=us-west1-a
    ```

2. Update the package list and install Apache2:

    ```sh
    sudo apt-get update
    sudo apt-get install apache2 -y
    ```

3. Start the Apache2 service:

    ```sh
    sudo systemctl start apache2
    ```

4. Enable Apache2 to start on boot:

    ```sh
    sudo systemctl enable apache2
    ```

### Task 4: Test Your Server

1. Get the external IP address of your VM instance:

    ```sh
    gcloud compute instances list --filter="name=dev-fin-oq6" --format="get(networkInterfaces[0].accessConfigs[0].natIP)"
    ```

2. Open a web browser and navigate to `http://<EXTERNAL_IP>`. You should see the "Hello World!" page.

## Troubleshooting

- If you receive a "Connection Refused" error, ensure that your VM instance has the proper tag and that the firewall rule allows traffic to the instance's external IP address.
- Make sure you are using `http://<EXTERNAL_IP>` and not `https://<EXTERNAL_IP>`.
