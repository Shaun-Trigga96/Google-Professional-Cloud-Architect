# Configure Secure RDP using a Windows Bastion Host: Challenge Lab

## Challenge scenario

- Your company has decided to deploy new application services in the cloud and your assignment is developing a secure framework for managing the Windows services that will be deployed. You will need to create a new VPC network environment for the secure production Windows servers.

- Production servers must initially be completely isolated from external networks and cannot be directly accessed from, or be able to connect directly to, the internet. In order to configure and manage your first server in this environment, you will also need to deploy a bastion host, or jump box, that can be accessed from the internet using the Microsoft Remote Desktop Protocol (RDP). The bastion host should only be accessible via RDP from the internet, and should only be able to communicate with the other compute instances inside the VPC network using RDP.

- Your company also has a monitoring system running from the default VPC network, so all compute instances must have a second network interface with an internal only connection to the default VPC network.

## Your challenge

Deploy the secure Windows machine that is not configured for external communication inside a new VPC subnet, then deploy the Microsoft Internet Information Server on that secure machine. For the purposes of this lab, all resources should be provisioned in the following region and zone:

- Region: us-east1
- Zone: us-east1-d

# Task 1: Create the VPC Network

## Create a new VPC network called securenetwork

1. Go to *VPC Network > VPC Networks* in the Google Cloud Console.
2. Click *Create VPC Network*.
3. Set the following:
   - *Name:* securenetwork
   - *Subnet creation mode:* Custom
4. Add a subnet:
   - *Subnet Name:* securenetwork-subnet
   - *Region:* us-east1
   - *IP range:* 10.0.0.0/24
5. Click *Create*.

### Shell Command

```bash
gcloud compute networks create securenetwork --subnet-mode=custom
```

### Create a new VPC subnet inside securenetwork in the us-east4 region

```bash
gcloud compute networks subnets create securesubnet \
    --network=securenetwork \
    --region=us-east1 \
    --range=10.0.0.0/24
```

### Create a firewall rule that allows inbound RDP traffic to the bastion host

1. Go to *VPC Network > Firewall Rules* in the Google Cloud Console.
2. Click *Create Firewall Rule*.
3. Set the following:
   - *Name:* allow-rdp-bastion
   - *Network:* securenetwork
   - *Targets:* Specified target tags
   - *Target tags:* bastion-host
   - *Source filter:* IP ranges
   - *Source IP ranges:* 0.0.0.0/0
   - *Protocols and ports:* Select *Specified protocols and ports* > Enable *TCP* > Enter 3389.
4. Click *Create*.

### Shell Command

```bash
gcloud compute firewall-rules create allow-rdp-bastion \
    --network=securenetwork \
    --allow=tcp:3389 \
    --source-ranges=0.0.0.0/0 \
    --target-tags=bastion-rdp
```

# Task 2: Deploy Your Windows Instances and Configure User Passwords

## Deploy a Windows 2016 server instance called vm-securehost with two network interfaces

1. Go to *Compute Engine > VM Instances* in the Google Cloud Console.
2. Click *Create Instance*.
3. Set the following:
   - *Name:* vm-securehost
   - *Zone:* us-east1-d
   - *Machine type:* Choose any suitable machine type (e.g., n1-standard-1).
   - *Boot disk:* Windows Server 2016 (Server with Desktop Experience)
4. Under *Network interfaces:*
   - *Interface 1:* Connect to securenetwork-subnet with *Internal* IP.
   - *Interface 2:* Connect to the default network with *Internal* IP.
5. Click *Create*.

### Shell Command

```bash
gcloud compute instances create vm-securehost \
    --zone=us-east1-d \
    --machine-type=n1-standard-1 \
    --network-interface=subnet=securesubnet,no-address \
    --network-interface=subnet=default,no-address \
    --image-family=windows-2016 \
    --image-project=windows-cloud \
    --tags=securehost
```

### Deploy a second Windows 2016 server instance called vm-bastionhost

1. Go to *Compute Engine > VM Instances* in the Google Cloud Console.
2. Click *Create Instance*.
3. Set the following:
   - *Name:* vm-bastionhost
   - *Zone:* us-east1-d
   - *Machine type:* Choose any suitable machine type (e.g., n1-standard-1).
   - *Boot disk:* Windows Server 2016 (Server with Desktop Experience)
4. Under *Network interfaces:*
   - *Interface 1:* Connect to securenetwork-subnet with *Ephemeral (NAT) External IP*.
   - *Interface 2:* Connect to the default network with *Internal* IP.
5. Click *Create*.

### Shell Command

```bash
gcloud compute instances create vm-bastionhost \
    --zone=us-east1-d \
    --machine-type=e2-medium \
    --image-family=windows-2016 \
    --image-project=windows-cloud \
    --network-interface=network=securenetwork,subnet=securenetwork-subnet,address-type=ephemeral \
    --network-interface=network=default,no-address \
    --tags=bastion-rdp
```

### Reset the Windows passwords for both instances

Use the following commands in *Cloud Shell*:
bash

### Reset password for vm-bastionhost

```bash
gcloud compute reset-windows-password vm-bastionhost --user app_admin --zone us-east1-d
```

### Reset password for vm-securehost

```bash
gcloud compute reset-windows-password vm-securehost --user app_admin --zone us-east1-d
```

Alternatively, reset passwords from the Compute Engine Console:

1. Select the VM instance.
2. Use the *Set Windows Password* option to reset the password.

# Task 3: Connect to the Secure Host and Configure Internet Information Server

## How do you connect to the secure host?

1. Connect to the *bastion host* via RDP:
   - Use the external IP address of vm-bastionhost and the app_admin credentials.
   - Use an RDP client like *Microsoft Remote Desktop*.

2. From the bastion host, connect to the *secure host*:
   - Open *Command Prompt* or *Run* dialog.
   - Type mstsc.exe and press Enter.
   - Enter the *internal IP address* of vm-securehost.
   - Use the app_admin credentials.

### How do you install and configure IIS on the secure host?

1. Open *Server Manager* on vm-securehost.
2. Click *Add Roles and Features*.
3. Select *Role-based or feature-based installation*.
4. Choose the current server.
5. Select *Web Server (IIS)* and click *Next*.
6. Keep the default settings and click *Install*.
7. After installation, verify by opening a browser and navigating to <http://localhost>.

### Shell Command

```bash
curl http://<SECURE_HOST_PRIVATE_IP>
```
