# kubectl Command Overview

## What is kubectl?

- **kubectl** is a utility used by administrators to control Kubernetes clusters.
- It communicates with the Kube API server on the control plane.
- Transforms command-line entries into API calls and sends them to the Kube API server.

## Importance of kubectl

- Allows users to make requests to the cluster.
- Determines which part of the control plane to communicate with.

## Configuration

- **kubectl** must be configured with the location and credentials of a Kubernetes cluster.
- Configuration is stored in a file in the home directory in a hidden folder named `.kube`.
- Contains the list of clusters and the credentials for each cluster.
- Credentials are provided through the `gcloud` command.
- View configuration with `kubectl config view`.

## Example Usage

- To see a list of Pods in a cluster: `kubectl get pod`.
- Converts command into an API call, sends it to the Kube API server, processes the request, and returns the results.

## Connecting to a GKE Cluster

- Retrieve credentials with the `get-credentials` gcloud command.
- Writes configuration information into a config file in the `.kube` directory.
- Configuration process only needs to be performed once per cluster in Cloud Shell.

## gcloud Command

- Used by authorized users to interact with Google Cloud from the command line.
- Provides credentials needed to connect with a GKE cluster.

## kubectl Syntax

- Composed of four parts: command, type, name, and optional flags.
  - **Command**: Specifies the action (e.g., get, describe, logs, exec).
  - **Type**: Defines the Kubernetes object (e.g., Pods, deployments, nodes).
  - **Name**: Specifies the object defined in type (optional).
  - **Flags**: Special requests or additional information (e.g., `-o=yaml`, `-o=wide`).

## Common Commands

- `kubectl get pods`: Lists all Pods.
- `kubectl get pod my-test-app`: Returns information on the Pod named 'my-test-app'.
- `kubectl get pod my-test-app -o=yaml`: Views the state of a Pod in YAML format.
- `kubectl get pods -o=wide`: Displays the list of Pods in wide format, showing which node each Pod is running on.

## Uses of kubectl

- Creating, viewing, deleting Kubernetes objects.
- Viewing or exporting configuration files.
- Ensure kubectl is configured first or use `--kubeconfig` or `--context` parameters to specify the cluster.

# Debugging with kubectl: Introspection

## Introduction to Introspection

- **Introspection**: Gathering information about containers, Pods, services, and other engines within the cluster.
- Key commands: `get`, `describe`, `exec`, and `logs`.

## Key Commands for Introspection

### 1. `kubectl get pods`

- **Purpose**: Check if a Pod is running.
- **Pod Phase Status**:
  - **Pending**: Pod accepted but not yet scheduled.
  - **Running**: Pod attached to a node and containers created.
  - **Succeeded**: Containers finished running successfully.
  - **Failed**: Container terminated with failure.
  - **Unknown**: State cannot be retrieved.
  - **CrashLoopBackOff**: Container exited unexpectedly and restarted.

### 2. `kubectl describe pod`

- **Purpose**: Detailed information about a Pod and its containers.
- **Pod Details**: Name, namespace, node name, labels, status, IP address.
- **Container Details**: State (waiting, running, terminated), images, ports, commands, restart counts.

### 3. `kubectl exec`

- **Purpose**: Run a single command inside a container.
- **Usage**: Useful for simple commands like `ping`.

### 4. `kubectl logs`

- **Purpose**: View logs inside a Pod.
- **Usage**: Troubleshoot errors or debugging messages.
- **Options**: Use `-c` argument to show logs for a specific container in a Pod.

## Advanced Usage

### Interactive Shell

- **Purpose**: Work inside a Pod to run commands or install packages.
- **Command**: `kubectl exec -it <pod-name> -- /bin/bash`
  - `-i`: Pass terminal’s standard input to the container.
  - `-t`: Input is a TTY.
- **Note**: Not best practice to install software directly into a container. Instead, build container images with required software.

## Best Practices

- Use introspection commands to gather information and troubleshoot.
- Integrate changes into container images and redeploy rather than temporary fixes.

# Deploying GKE Autopilot Clusters from Cloud Shell

## Overview
In this lab, you use the command line to build GKE clusters, inspect the kubeconfig file, and use kubectl to manipulate the cluster.

## Objectives

In this lab, you will learn how to:

- Use kubectl to build and manipulate GKE clusters.
- Use kubectl and configuration files to deploy Pods.
- Use Container Registry to store and deploy containers.

## Task 1: Deploy GKE Clusters

In this task, you use Cloud Shell to deploy GKE clusters.

### Steps

1. **Set Environment Variables**:

   ```sh
   export my_region=Region
   export my_cluster=autopilot-cluster-1
   ```

2. **Create a Kubernetes Cluster**:

   ```sh
   gcloud container clusters create-auto $my_cluster --region $my_region
   ```

   - Wait a few minutes for the cluster deployment to complete.
   - Verify the deployment in the Google Cloud Console under Kubernetes Engine > Clusters.

## Task 2: Connect to a GKE Cluster

In this task, you use Cloud Shell to authenticate to a GKE cluster and inspect the kubectl configuration files.

### Steps

1. **Authenticate to the Cluster**:

   ```sh
   gcloud container clusters get-credentials $my_cluster --region $my_region
   ```

   - This command creates a `.kube` directory and a `config` file if they don't already exist.

2. **Inspect the kubeconfig File**:

   ```sh
   nano ~/.kube/config
   ```

   - Examine the authentication and endpoint configuration data.
   - Exit the nano editor with `CTRL+X`.

## Task 3: Use kubectl to Inspect a GKE Cluster

In this task, you use Cloud Shell and kubectl to inspect a GKE cluster.

### Steps

1. **View kubeconfig File**:

   ```sh
   kubectl config view
   ```

2. **Print Cluster Information**:

   ```sh
   kubectl cluster-info
   ```

3. **Print Active Context**:

   ```sh
   kubectl config current-context
   ```

4. **Get Contexts**:

   ```sh
   kubectl config get-contexts
   ```

5. **Change Active Context**:

   ```sh
   kubectl config use-context gke_${DEVSHELL_PROJECT_ID}_Region_autopilot-cluster-1
   ```

6. **Enable Bash Autocompletion for kubectl**:

   ```sh
   source <(kubectl completion bash)
   ```

7. **Use Tab Completion**:
   - Type `kubectl` followed by a space and press the Tab key twice to see all possible commands.
   - Type `kubectl co` and press the Tab key twice to see all commands starting with "co".

# Push a File into a Container

## Overview

To serve static content through the nginx web server, you must create and place a file into the container.

## Steps

### 1. Create and Edit the File

- **Open a file named `test.html` in the nano text editor**:

  ```sh
  nano ~/test.html
  ```

- **Add the following text to the file**:

  ```html
  <html>
    <head><title>This is title</title></head>
    <body>Hello world</body>
  </html>
  ```

- **Save and exit nano**:
  - Press `CTRL+X`, then `Y`, and `Enter`.

### 2. Copy the File into the nginx Container

- **Copy the file into the appropriate location within the nginx container**:

  ```sh
  kubectl cp ~/test.html $my_nginx_pod:/usr/share/nginx/html/test.html
  ```

## Expose the Pod for Testing

### 1. Create a Service to Expose the Pod

- **Create a LoadBalancer service**:

  ```sh
  kubectl expose pod $my_nginx_pod --port 80 --type LoadBalancer
  ```

### 2. View Service Details

- **View details about services in the cluster**:

  ```sh
  kubectl get services
  ```

  - Example output:

    ```sh
    NAME             TYPE         CLUSTER-IP    EXTERNAL-IP    PORT(S)     AGE
    kubernetes       ClusterIP    10.11.240.1   <none>         443/TCP     1h
    nginx-1-7...wsc  LoadBalancer 10.11.240.87  104.154.177.46 80:31695/TCP 1m
    ```

### 3. Verify the nginx Container is Serving the Static HTML File

- **Use `curl` to verify**:

  ```sh
  curl http://[EXTERNAL_IP]/test.html
  ```

  - Replace `[EXTERNAL_IP]` with the external IP address of your service.
  - Example output:

    ```html
    <html>
      <head><title>This is title</title></head>
      <body>Hello world</body>
    </html>
    ```

### 4. View Resource Usage by the nginx Pod

- **View the resources being used by the nginx Pod**:

  ```sh
  kubectl top pods
  ```

  - Example output:

    ```sh
    NAME                       CPU(cores)   MEMORY(bytes)
    nginx-1-74c7bbdb84-nvwsc   0m           2Mi
    ```

# Task 5: Introspect GKE Pods

## Overview
In this task, you connect to a Pod to adjust settings, edit files, and make other live changes to the Pod. Use this process only for troubleshooting or experimenting, as changes won't be present in any replicas.

## Steps

### Prepare the Environment

1. **Clone the Repository**:

   ```sh
   git clone https://github.com/GoogleCloudPlatform/training-data-analyst
   ```

2. **Create a Soft Link**:

   ```sh
   ln -s ~/training-data-analyst/courses/ak8s/v1.1 ~/ak8s
   ```

3. **Change to the Directory**:

   ```sh
   cd ~/ak8s/GKE_Shell/
   ```

### Deploy the Manifest

1. **Sample Manifest YAML**:

   ```yaml
   apiVersion: v1
   kind: Pod
   metadata:
     name: new-nginx
     labels:
       name: new-nginx
   spec:
     containers:
     - name: new-nginx
       image: nginx
       ports:
       - containerPort: 80
   ```

2. **Deploy the Manifest**:

   ```sh
   kubectl apply -f ./new-nginx-pod.yaml
   ```

3. **List Pods**:

   ```sh
   kubectl get pods
   ```

   - Example output:

     ```sh
     NAME                       READY     STATUS    RESTARTS   AGE
     new-nginx                  1/1       Running   0          9s
     nginx-1-74c7bbdb84-nvwsc   1/1       Running   0          55m
     ```

### Use Shell Redirection to Connect to a Pod

1. **Start an Interactive Bash Shell**:

   ```sh
   kubectl exec -it new-nginx -- /bin/bash
   ```

   - Example output:

     ```sh
     root@new-nginx:/#
     ```

2. **Install nano Text Editor**:

   ```sh
   apt-get update
   apt-get install nano
   ```

   - Confirm with `Y` when prompted.

3. **Create a test.html File**:

   ```sh
   cd /usr/share/nginx/html
   nano test.html
   ```

   - Add the following text:

     ```html
     <html>
       <head><title>This is title</title></head>
       <body>Hello world</body>
     </html>
     ```

   - Save and exit nano (`CTRL+X`, `Y`, `Enter`).

4. **Exit the nginx Bash Shell**:

   ```sh
   exit
   ```

### Port Forwarding to Test the Pod

1. **Set Up Port Forwarding**:

   ```sh
   kubectl port-forward new-nginx 10081:80
   ```

   - Example output:

     ```sh
     Forwarding from 127.0.0.1:10081 -> 80
     Forwarding from [::1]:10081 -> 80
     ```

2. **Open a New Cloud Shell Session**:
   - Click the plus sign (+) icon in the Cloud Shell menu bar.

3. **Test the Modified nginx Container**:

   ```sh
   curl http://127.0.0.1:10081/test.html
   ```

   - Example output:

     ```html
     <html>
       <head><title>This is title</title></head>
       <body>Hello world</body>
     </html>
     ```

### View the Logs of a Pod

1. **Open Another New Cloud Shell Session**:
   - Click the plus sign (+) icon in the Cloud Shell menu bar.

2. **Display and Stream Logs**:

   ```sh
   kubectl logs new-nginx -f --timestamps
   ```

3. **Generate Traffic on the Pod**:
   - Return to the second Cloud Shell window and re-run the `curl` command.

4. **Review Log Messages**:
   - Review the additional log messages as they appear in the third Cloud Shell window.

5. **Close Cloud Shell Windows**:
   - Close the third Cloud Shell window to stop displaying the log messages.
   - Close the original Cloud Shell window to stop the port forwarding process.
