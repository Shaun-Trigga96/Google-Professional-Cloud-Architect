# Using NAT for Apigee X Backend Services

## Overview

In this lab, you will enable a NAT (Network Address Translation) IP address for requests from an Apigee instance to backend services. This creates a predictable IP address that can be allow-listed for secure communication.

## Objectives

- Call the Apigee API from the Apigee API documentation.
- Create and activate a NAT IP address for Apigee requests coming from the Apigee runtime.
- Confirm that requests to a backend server use the configured NAT IP address.

---

## Task 1: Explore the Apigee API Documentation

### Steps

1. **Open the Google APIs Explorer**:
   - Copy and paste the following link into a new browser tab: [Google APIs Explorer for the Apigee API](https://developers.google.com/apis-explorer/#search/apigee/).
   - This tool allows you to explore and test the Apigee API directly.

2. **Navigate to the `v1.organizations.instances` REST Resource**:
   - In the right pane, locate the `v1.organizations.instances` section.
   - Click on the **list** method to view its details.

3. **Test the API**:
   - In the **Try this API** pane, set the `parent` parameter to:

     ```
     organizations/PROJECT
     ```

   - Click **Execute**.
   - If prompted, select your lab account and click **Allow**.

4. **Review the Response**:
   - The response should resemble one of the following:

     ```json
     {
       "instances": [
         {
           "name": "eval-instance",
           "location": "ZONE",
           "host": "172.21.60.2",
           "port": "443",
           "state": "ACTIVE"
         }
       ]
     }
     ```

     or

     ```json
     {
       "instances": [
         {
           "name": "eval-instance",
           "location": "europe-west1",
           "createdAt": "1706780597609",
           "lastModifiedAt": "1706780670711",
           "state": "CREATING",
           "peeringCidrRange": "SLASH_22",
           "runtimeVersion": "1-11-0-apigee-14",
           "ipRange": "10.188.120.0/28"
         }
       ]
     }
     ```

   - The instance name is `eval-instance`. You will create a NAT IP address for this instance.

5. **Explore Additional Details**:
   - Click the **Expand** icon in the upper right corner of the **Try this API** pane to view the cURL equivalent, HTTP request, and JavaScript code snippet.
   - Click **Revert** to close the expanded pane.

## Task 2: Wait for Instance Provisioning to Complete

### Steps

1. **Open Cloud Shell**:
   - Return to the **Cloud Console** tab.
   - Click the **Activate Cloud Shell** button in the top-right toolbar.
   - If prompted, click **Continue**.

2. **Verify Project Variable**:
   - In Cloud Shell, verify the `GOOGLE_CLOUD_PROJECT` variable:

     ```bash
     echo ${GOOGLE_CLOUD_PROJECT}
     ```

   - If the variable is not set, set it manually:

     ```bash
     export GOOGLE_CLOUD_PROJECT={project}
     ```

     Replace `{project}` with your project name (remove curly braces).

3. **Monitor Provisioning**:
   - Paste the following command into Cloud Shell to monitor the provisioning progress:

     ```bash
     export INSTANCE_NAME=eval-instance; export ENV_NAME=eval; export PREV_INSTANCE_STATE=; echo "waiting for runtime instance ${INSTANCE_NAME} to be active"; while : ; do export INSTANCE_STATE=$(curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" -X GET "https://apigee.googleapis.com/v1/organizations/${GOOGLE_CLOUD_PROJECT}/instances/${INSTANCE_NAME}" | jq "select(.state != null) | .state" --raw-output); [[ "${INSTANCE_STATE}" == "${PREV_INSTANCE_STATE}" ]] || (echo; echo "INSTANCE_STATE=${INSTANCE_STATE}"); export PREV_INSTANCE_STATE=${INSTANCE_STATE}; [[ "${INSTANCE_STATE}" != "ACTIVE" ]] || break; echo -n "."; sleep 5; done; echo; echo "instance created, waiting for environment ${ENV_NAME} to be attached to instance"; while : ; do export ATTACHMENT_DONE=$(curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" -X GET "https://apigee.googleapis.com/v1/organizations/${GOOGLE_CLOUD_PROJECT}/instances/${INSTANCE_NAME}/attachments" | jq "select(.attachments != null) | .attachments[] | select(.environment == \"${ENV_NAME}\") | .environment" --join-output); [[ "${ATTACHMENT_DONE}" != "${ENV_NAME}" ]] || break; echo -n "."; sleep 5; done; echo; echo "${ENV_NAME} environment attached"; echo "***ORG IS READY TO USE***";
     ```

   - This script monitors the creation of the runtime instance and the attachment of the `eval` environment.

4. **Wait for Completion**:
   - Wait until the message `***ORG IS READY TO USE***` is printed.
   - If the command indicates the org is ready immediately, the lab may have been prewarmed.

## Notes

- The NAT IP address ensures that requests from the Apigee runtime to backend services use a predictable IP address, which can be allow-listed for secure communication.
- Ensure the instance provisioning is complete before proceeding to the next tasks.

# Task 3: Create and Deploy an API Proxy

In this task, you will create an API proxy to test the IP address seen by a backend service.

## Steps to Create and Deploy the API Proxy

1. **Open the Apigee Console**:
   - Select the **Apigee Console** tab in your browser.
   - Navigate to **Develop > API Proxies**.

2. **Select the Environment**:
   - In the **Select Environment** dropdown, choose **eval**.
   - If the dropdown does not show the `eval` environment, refresh the page.

3. **Start the Proxy Wizard**:
   - Click **Create New**.
   - Select **Reverse proxy (most common)** (do not click "Use OpenAPI Spec").

4. **Specify Proxy Properties**:
   - **Name**: `test-nat`
   - **Base Path**: `/test-nat`
   - **Target (Existing API)**: `https://httpbin.org/ip`
   - Click **Next**.

5. **Configure Common Policies**:
   - Leave the default settings and click **Next**.

6. **Create and Deploy the Proxy**:
   - On the **Summary** page, select **eval**.
   - Click **Create and deploy**.
   - Click **Edit proxy**.

7. **Switch to Classic View**:
   - If a **Switch to Classic** link appears in the upper right corner, click it.

8. **Verify Deployment**:
   - Go to the **Overview** tab.
   - Wait for the deployment status to show that **Revision 1** is deployed to the `eval` environment.

# Task 4: Test the API Proxy

In this task, you will make calls to the API proxy to observe the dynamic IP address used for backend services.

## Steps to Test the API Proxy

1. **Connect to the Test VM**:
   - In **Cloud Shell**, run the following commands to SSH into the VM:

     ```bash
     TEST_VM_ZONE=$(gcloud compute instances list --filter="name=('apigeex-test-vm')" --format "value(zone)")
     gcloud compute ssh apigeex-test-vm --zone=${TEST_VM_ZONE} --force-key-file-overwrite
     ```

   - Press **Enter** for all default inputs.

2. **Set Shell Variables**:
   - Run the following commands to set required variables:

     ```bash
     export PROJECT_NAME=$(gcloud config get-value project)
     export ORG=${PROJECT_NAME}
     export INSTANCE_NAME=eval-instance
     export INTERNAL_LB_IP=$(curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" -X GET "https://apigee.googleapis.com/v1/organizations/${ORG}/instances/${INSTANCE_NAME}" | jq ".host" --raw-output)
     export EVAL_ENVGROUP_HOSTNAME=$(curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" -X GET "https://apigee.googleapis.com/v1/organizations/${ORG}/envgroups/eval-group" | jq ".hostnames[0]" --raw-output)
     echo "INTERNAL_LB_IP=${INTERNAL_LB_IP}"
     echo "EVAL_ENVGROUP_HOSTNAME=${EVAL_ENVGROUP_HOSTNAME}"
     ```

3. **Call the API Proxy**:
   - Run the following command to call the `test-nat` proxy in the `eval` environment:

     ```bash
     curl -k "https://${EVAL_ENVGROUP_HOSTNAME}/test-nat"
     ```

   - The `-k` option skips TLS certificate verification (for testing purposes only).

4. **Review the Response**:
   - The response should resemble:

     ```json
     {
       "origin": "10.0.0.2,10.0.0.5,10.0.0.7, 34.83.164.141"
     }
     ```

   - The `origin` field shows multiple IP addresses. The last IP address is the one used to call the `httpbin.org` server.

# Task 5: Create a NAT IP for the Instance

In this task, you will create a NAT IP address for the Apigee instance to provide a predictable IP address for backend service calls.

## Steps to Create a NAT IP

1. **Open the Apigee API Explorer**:
   - Return to the **Apigee API Explorer** tab.

2. **Navigate to the `create` Method**:
   - In the left pane, expand **organizations.instances.natAddresses**.
   - Click **create**.

3. **Set Parameters**:
   - In the **Try this API** pane, set the `parent` parameter to:

     ```ssh
     organizations/PROJECT/instances/eval-instance
     ```

   - Click **Add request body parameters**, then set the `name` parameter to:

     ```ssh
     eval-instance-ip
     ```

   - Click **Execute**.

4. **Review the Response**:
   - The response should resemble:

     ```json
     {
       "name": "organizations/qwiklabs-gcp-01-f24706170325/operations/c79a19c8-ae9f-49de-978e-7f4873b06e51",
       "metadata": {
         "@type": "type.googleapis.com/google.cloud.apigee.v1.OperationMetadata",
         "operationType": "INSERT",
         "targetResourceName": "organizations/qwiklabs-gcp-01-f24706170325/instances/eval-instance/natAddresses/eval-instance-ip",
         "state": "IN_PROGRESS"
       }
     }
     ```

# Task 6: Activate the NAT IP

In this task, you will activate the NAT IP address.

## Steps to Activate the NAT IP

1. **Navigate to the `activate` Method**:
   - In the left pane, under **organizations.instances.natAddresses**, click **activate**.

2. **Set Parameters**:
   - In the **Try this API** pane, set the `parent` parameter to:

     ```ssh
     organizations/PROJECT/instances/eval-instance/natAddresses/eval-instance-ip
     ```

   - Click **Execute**.

3. **Review the Response**:
   - The response should resemble:

     ```json
     {
       "name": "organizations/qwiklabs-gcp-01-f24706170325/operations/4b96ee01-55a5-4824-859a-04c2e034d1d4",
       "metadata": {
         "@type": "type.googleapis.com/google.cloud.apigee.v1.OperationMetadata",
         "operationType": "INSERT",
         "targetResourceName": "organizations/qwiklabs-gcp-01-f24706170325/instances/eval-instance/natAddresses/eval-instance-ip",
         "state": "IN_PROGRESS"
       }
     }
     ```

4. **Verify Activation**:
   - Use the **get** method under **organizations.instances.natAddresses** to check the NAT IP status.
   - The response should show:

     ```json
     {
       "name": "eval-instance-ip",
       "ipAddress": "104.198.6.224",
       "state": "ACTIVE"
     }
     ```

# Task 7: Test the NAT Address

In this task, you will verify that the NAT IP address is used for backend service calls.

## Steps to Test the NAT Address

1. **Reconnect to the VM**:
   - If the SSH connection has dropped, reconnect using:

     ```bash
     TEST_VM_ZONE=$(gcloud compute instances list --filter="name=('apigeex-test-vm')" --format "value(zone)")
     gcloud compute ssh apigeex-test-vm --zone=${TEST_VM_ZONE} --force-key-file-overwrite
     ```

2. **Set Shell Variables**:
   - Run the following commands:

     ```bash
     export PROJECT_NAME=$(gcloud config get-value project)
     export ORG=${PROJECT_NAME}
     export INSTANCE_NAME=eval-instance
     export NAT_ADDR_NAME=eval-instance-ip
     export INTERNAL_LB_IP=$(curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" -X GET "https://apigee.googleapis.com/v1/organizations/${ORG}/instances/${INSTANCE_NAME}" | jq ".host" --raw-output)
     export EVAL_ENVGROUP_HOSTNAME=$(curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" -X GET "https://apigee.googleapis.com/v1/organizations/${ORG}/envgroups/eval-group" | jq ".hostnames[0]" --raw-output)
     export NAT_IP_ADDRESS=$(curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" -X GET "https://apigee.googleapis.com/v1/organizations/${ORG}/instances/${INSTANCE_NAME}/natAddresses/${NAT_ADDR_NAME}" | jq ".ipAddress" --raw-output)
     echo "INTERNAL_LB_IP=${INTERNAL_LB_IP}"
     echo "EVAL_ENVGROUP_HOSTNAME=${EVAL_ENVGROUP_HOSTNAME}"
     echo "NAT_IP_ADDRESS=${NAT_IP_ADDRESS}"
     ```

3. **Call the API Proxy**:
   - Run the following command:

     ```bash
     curl -k "https://${EVAL_ENVGROUP_HOSTNAME}/test-nat"
     ```

   - The response should now show the NAT IP address as the last IP in the `origin` field:

     ```json
     {
       "origin": "10.0.0.2,10.0.0.5,10.0.0.6, 104.198.6.224"
     }
     ```

4. **Confirm the NAT IP**:
   - Verify the NAT IP address matches the one retrieved from the Apigee API.

## Notes

- The NAT IP address ensures a predictable IP for backend service calls, which can be allow-listed for secure communication.
- Avoid using the `-k` option to skip TLS verification in production environments.
