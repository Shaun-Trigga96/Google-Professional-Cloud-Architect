# Fundamental Concept: Infrastructure as Code (IaC)

## Introduction to IaC

With IaC, you can write code using a configuration language to define, provision, and manage your infrastructure. Gone are the days where a system administrator had to manually configure hundreds of servers, networks, and firewall rules by interacting with a user interface. With IaC, you only declare the desired end state of the infrastructure – IaC handles management and provisioning.

## DevOps and IaC

The rapid increase of business demand has manifested a cultural shift known as DevOps. DevOps emphasizes collaboration and communication between developer and operations teams, and automates software delivery and infrastructure changes.

### Challenges Addressed by IaC

1. **High Business Demand**: Requires rapid scaling of IT infrastructure across industries.
2. **Operational and Technical Bottlenecks**: Managing infrastructure consistently at scale.
3. **Collaboration and Auditing**: Struggles in collaborating and auditing changes.
4. **Human Error**: Increased quantity and scale lead to potential manual errors.

## Benefits of IaC

1. **Declarative Nature**: Focus on the desired state of the infrastructure rather than the exact sequence of steps.
   - Example: Use a production label to specify three subnets across two regions. Terraform updates the live state to match the desired state.
2. **Managed as Code**: Infrastructure is managed like application source code.
   - Full history of versions and changes.
   - Ability to roll back to previous states.
   - Collaboration through version control.
3. **Auditable History**: Clear view of infrastructure evolution with explanations and comments.
4. **Portability**: Build reusable modules for consistent infrastructure deployment.
   - Google Cloud's Cloud Foundation Toolkit provides reusable modules.

## Provisioning vs. Configuration Management

- **Provisioning**: IaC is used for provisioning and managing cloud resources.
- **Configuration Management**: Used for VM OS-level configuration.
  - Example: IaC creates and provisions a VM instance, while configuration management configures the internals of the VMs.

## Declarative vs. Imperative Models

- **Imperative Model**: Specifies exact actions (e.g., create five servers).
  - Challenges: Difficult to determine the difference between live infrastructure and desired state.
- **Declarative Model**: Declares the desired state of infrastructure.
  - Example: Declare five servers; Terraform creates or restores servers as needed.

## Conclusion

Adopting declarative infrastructure tools like Terraform allows you to focus on how the infrastructure should be, and let automation handle the details of updating the infrastructure to match your desired state. Declarative management focuses on the WHAT rather than the HOW.

# Introduction to Terraform

## What is Terraform?

Terraform is an infrastructure as code (IaC) tool created by HashiCorp, currently licensed under the HashiCorp Business Source License v1.1. It lets you provision Google Cloud resources with declarative configuration files. Examples of resources include virtual machines, containers, storage, and networks.

Terraform allows infrastructure to be expressed as code in a simple, human-readable language called HashiCorp Configuration Language (HCL). Terraform reads configuration files and provides an execution plan of changes, which can be reviewed, applied, and provisioned.

At a high level, Terraform lets operators author files containing resource definitions on the Google Cloud provider and automates the creation of those resources.

## Terraform Features

- **Multi-cloud and multi-API support**: Supports all major cloud providers, in addition to Google Cloud and API-exposed services such as GitHub and Kubernetes.
- **Editions**: Three different editions ranging from self-hosted to fully managed, including enterprise support.
- **Community**: A large community, including a registry with publicly available modules for Google Cloud deployments.
- **Infrastructure Provisioning**: Focuses on provisioning rather than configuration.

## Using Terraform for Google Cloud

- **Resource Blocks**: Define infrastructure elements such as VMs, networks, and firewalls.
- **Dependencies**: Create explicit dependencies between resources.
- **Reusable Modules**: Standardize resource creation.
- **Validation Rules**: Limit the values provided for a given resource argument.

## Standard IaC Configuration Workflow

1. **Scope**: Determine what resources should be created for a project.
   - Example: For a common 2-tier architecture, scope the type of compute and database instances needed.
2. **Author**: Author the configuration code for the infrastructure.
   - Example: Code the configuration of the instances and the VPC network.
3. **Organize**: Organize your code in configuration files (e.g., variables, main, tfvars).
4. **Initialize**: Install any plugins or modules.
   - Command: `terraform init`
5. **Plan**: Provide an execution plan for the resources.
   - Command: `terraform plan`
6. **Apply**: Review and apply the configuration to create the infrastructure and a state file.

## Common Terraform Use Cases

- **Manage Infrastructure**: Write code to reduce complexity in upgrading or modifying services and infrastructure.
- **Track Infrastructure Changes**: Approve changes before modifying the state of the infrastructure.
- **Automate Changes**: Define the end state; Terraform manages dependencies and provisions resources.
- **Standardize Configurations**: Use modules to save time and implement best practices.
- **Enforce Policies**: Automate the enforcement of policies on the types of resources teams can provision and use.

## Conclusion

Terraform is a powerful tool for managing and automating your Google Cloud infrastructure. By using declarative configuration files, you can efficiently provision, manage, and track changes to your infrastructure, ensuring consistency and reducing the risk of manual errors.

# Using Terraform to Manage Infrastructure Resources

## Writing Infrastructure as Code

First, you must write your infrastructure as code in configuration files. These files describe to Terraform the resources you want to provision. Terraform generates an execution plan for the desired state, and then executes the plan to build the described infrastructure. As the configuration changes, Terraform can determine what changed and create incremental execution plans that can be applied.

## Terraform Editions

Terraform is available in three editions:

1. **Community Edition**:
   - Free version available for download on a local machine or cloud compute resource.
   - Many features available with no license cost.
   - Grants access to publicly available templates.
   - Only usable on a local machine, no support for concurrent deployments.
   - No version control, only CLI interaction.

2. **Terraform Cloud**:
   - Useful for collaborative environments.
   - Three plans: Free, Standard, and Plus.
   - Supports concurrent deployment.
   - Low operational overhead.

3. **Terraform Enterprise**:
   - Hosted on-premises or on infrastructure controlled by you.
   - High operational overhead due to infrastructure maintenance.
   - Integration with Terraform.

## Installing Terraform

Terraform is pre-installed on Cloud Shell, but you can also install it on your local machine. You can install Terraform as a binary package or use popular package managers.

### Manual Installation on Windows

1. Download the package that meets your system requirements.
2. Extract the package.
3. Terraform includes a single binary called `terraform`.
4. Edit the PATH variable to include Terraform.
5. Verify the installation by entering `terraform -help` in a new terminal.

## Authentication Mechanisms

The authentication mechanism used for Google Cloud varies based on where Terraform is run. The Google Cloud provider will require authentication to communicate with the resource API for resource creation.

- **Terraform on Cloud Shell**: Pre-authenticated.
- **Terraform on Workstation**: Authenticate using the Cloud SDK.
  - Install `gcloud CLI`.
  - Run `gcloud auth application-default login` to authenticate with Google Cloud.
- **Terraform in a VM on Google Cloud**: Configure the VM to use a Google Service Account.
  - Ensure the VM has the Google Cloud API enabled.
- **Terraform outside Google Cloud**: Use a Google Cloud Service Account.
  - Download the JSON key file from the service account key page in the Cloud Console.
  - Set the environment variable `GOOGLE_APPLICATION_CREDENTIALS` to the location of the file.

## Creating a Simple VPC Network

Once you’ve downloaded Terraform and authenticated successfully, you’re ready to start authoring a Terraform configuration. Let’s create a simple VPC network.

1. Create a configuration file with a `.tf` extension.
2. Define Google Cloud as the provider.
3. Add HCL code to create a Google Compute instance.
4. Save the code.
5. Navigate to the directory where you saved the file.
6. Run `terraform init`, `terraform plan`, and `terraform apply`.

After you run `terraform apply`, a new VPC network named `mynetwork` will be created on Google Cloud.

## Conclusion

Terraform simplifies the process of creating, updating, and destroying infrastructure resources by using configuration files to describe the desired state. With different editions available, you can choose the one that best fits your needs, whether for individual use or collaborative environments.
