# Optimize Costs for Google Kubernetes Engine: Challenge Lab

## Challenge scenario

- You are the lead Google Kubernetes Engine admin on a team that manages the online shop for OnlineBoutique.

- You are ready to deploy your team's site to Google Kubernetes Engine but you are still looking for ways to make sure that you're able to keep costs down and performance up.

- You will be responsible for deploying the OnlineBoutique app to GKE and making some configuration changes that have been recommended for cost optimization.

## Here are some guidelines you've been requested to follow when deploying

- Create the cluster in the us-east4-a zone.
- The naming scheme is team-resource-number, e.g. a cluster could be named onlineboutique-cluster-426.
- For your initial cluster, start with machine size e2-standard-2 (2 vCPU, 8G memory).
- Set your cluster to use the rapid release-channel.

# Task 1: Create a cluster and deploy your app

1. **Set your zone and create the cluster:**

   ```bash
   gcloud config set compute/zone us-east4-a
   gcloud container clusters create onlineboutique-cluster-426 \
       --machine-type=e2-standard-2 \
       --num-nodes=2 \
       --release-channel=rapid
   ```

2. **Create namespaces for dev and prod:**

   ```bash
   kubectl create namespace dev
   kubectl create namespace prod
   ```

3. **Deploy the application to the dev namespace:**

   ```bash
   git clone https://github.com/GoogleCloudPlatform/microservices-demo.git
   cd microservices-demo
   kubectl apply -f ./release/kubernetes-manifests.yaml --namespace dev
   ```

# Task 2: Migrate to an optimized node pool

1. **Create a new node pool named `optimized-pool-9452`:**

   ```bash
   gcloud container node-pools create optimized-pool-9452 \
       --cluster=onlineboutique-cluster-426 \
       --machine-type=custom-2-3584 \
       --num-nodes=2
   ```

2. **List nodes to find the default node names:**

   ```bash
   kubectl get nodes
   ```

3. **Cordon and drain the default node pool:**

   ```bash
   kubectl cordon gke-onlineboutique-cluster-426-default-pool-<node-id>
   kubectl drain gke-onlineboutique-cluster-426-default-pool-<node-id> --ignore-daemonsets --delete-local-data
   ```

4. **Delete the default node pool:**

   ```bash
   gcloud container node-pools delete default-pool --cluster=onlineboutique-cluster-426
   ```

# Task 3: Apply a frontend update

1. **Set a pod disruption budget:**

   ```bash
   kubectl create pdb onlineboutique-frontend-pdb \
       --namespace=dev \
       --selector=app=frontend \
       --min-available=1
   ```

2. **Update the frontend deployment:**

   ```bash
   kubectl set image deployment/frontend \
       frontend=gcr.io/qwiklabs-resources/onlineboutique-frontend:v2.1 \
       --namespace=dev
   kubectl patch deployment frontend \
       --namespace=dev \
       --patch '{"spec": {"template": {"spec": {"containers": [{"name": "frontend", "imagePullPolicy": "Always"}]}}}}'
   ```

# Task 4: Autoscale from estimated traffic

1. **Apply horizontal pod autoscaling to the frontend deployment:**

   ```bash
   kubectl autoscale deployment frontend \
       --cpu-percent=50 \
       --min=1 \
       --max=12 \
       --namespace=dev
   ```

2. **Update the cluster autoscaler:**

   ```bash
   gcloud container clusters update onlineboutique-cluster-426 \
       --enable-autoscaling \
       --min-nodes=1 \
       --max-nodes=6
   ```

3. **Run a load test:**

   ```bash
   kubectl exec $(kubectl get pod --namespace=dev | grep 'loadgenerator' | cut -f1 -d ' ') -it --namespace=dev -- bash -c 'export USERS=8000; locust --host="http://YOUR_FRONTEND_EXTERNAL_IP" --headless -u "8000" 2>&1'
   ```

4. **Apply horizontal pod autoscaling to the recommendationservice deployment:**

   ```bash
   kubectl autoscale deployment recommendationservice \
       --cpu-percent=50 \
       --min=1 \
       --max=5 \
       --namespace=dev
   ```
